## 🎯 Project Overview

**Evolution of Todo** is a progressive full-stack application that demonstrates modern software engineering practices through **Spec-Driven Development (SDD)**. The project evolves from a simple command-line interface to a production-ready, cloud-native web application—showcasing how AI agents like Claude Code can transform specifications into working software without manual coding.

### Key Highlights

✨ **Spec-Driven Development**: Every feature starts with a detailed specification in Markdown
🤖 **AI-Generated Code**: 100% of the code was generated by Claude Code
📊 **Test-Driven**: 82-85% test coverage across all phases
🏗️ **Production-Ready**: Deployed on Railway (backend) and Vercel (frontend)
🔒 **Enterprise Security**: JWT authentication, user isolation, HTTPS
📱 **Modern UX**: Responsive design, optimistic updates, real-time feedback

## 🚀 Hackathon Journey

This project was built for **Hackathon II: Spec-Driven Development**, where participants act as **system architects** rather than syntax writers. Every line of code was generated by Claude Code following a rigorous specification workflow.

### Database Schema (Neon PostgreSQL)

#### Tasks Table
(Existing from Phase II)
```sql
CREATE TABLE tasks (
    id SERIAL PRIMARY KEY,
    user_id VARCHAR(255) NOT NULL,
    title VARCHAR(200) NOT NULL,
    description VARCHAR(1000),
    complete BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_tasks_user_id ON tasks(user_id);
```

#### Conversation Table
```sql
CREATE TABLE conversation (
    id SERIAL PRIMARY KEY,
    user_id VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_conversation_user_id ON conversation(user_id);
```

#### Message Table
```sql
CREATE TABLE message (
    id SERIAL PRIMARY KEY,
    conversation_id INTEGER NOT NULL REFERENCES conversation(id),
    user_id VARCHAR(255) NOT NULL,
    role VARCHAR(20) NOT NULL,
    content TEXT NOT NULL,
    created_at TIMESTAMP DEFAULT NOW()
);

CREATE INDEX idx_message_conversation_id ON message(conversation_id);
CREATE INDEX idx_message_user_id ON message(user_id);
```

### Authentication Flow

```
User → Frontend (Better Auth) → Issues JWT
  ↓
JWT stored in httpOnly cookie (XSS protection)
  ↓
All API requests include JWT in Authorization: Bearer <token>
  ↓
Backend validates JWT signature using shared secret
  ↓
Extracts user_id from JWT payload
  ↓
Filters all DB queries by user_id (data isolation)
  ↓
Returns only user's own tasks
```

**Security Benefits**:
- ✅ Stateless authentication (no session DB)
- ✅ Automatic token expiry
- ✅ httpOnly cookies prevent XSS attacks
- ✅ JWT validation on every request
- ✅ User data isolation at database level

### Quick Start (Phase II: Full-Stack Web Application)

#### 1. Clone Repository

```bash
git clone https://github.com/your-username/hackathon-todo-fullstack.git
cd hackathon-todo-fullstack
```

#### 2. Backend Setup

```bash
cd phase-2-fullstack/backend

# Install dependencies
uv sync

# Configure environment
cp .env.example .env
# Edit .env with your Neon DATABASE_URL and JWT_SECRET_KEY

# Run migrations (creates tables)
python -c "from src.database import init_db, get_engine; init_db(get_engine())"

# Start backend server
uvicorn src.main:app --reload --host 0.0.0.0 --port 8000
```

**Backend runs at**: `http://localhost:8000`
**API Docs (Swagger)**: `http://localhost:8000/docs`

#### 3. Frontend Setup

```bash
cd ../../frontend

# Install dependencies
npm install

# Configure environment
cp .env.example .env.local
# Edit .env.local with:
#   - DATABASE_URL (same as backend)
#   - BETTER_AUTH_SECRET (generate with: openssl rand -base64 32)
#   - JWT_SECRET_KEY (must match backend)
#   - NEXT_PUBLIC_API_URL=http://localhost:8000

# Run Better Auth migrations
npx @better-auth/cli migrate --config lib/auth/auth.ts

# Start frontend server
npm run dev
```

**Frontend runs at**: `http://localhost:3000`

#### 4. Access the Application

1. Open `http://localhost:3000`
2. Click **"Sign Up"** to create an account
3. Enter email and password (min 8 characters)
4. You'll be auto-logged in and redirected to the dashboard
5. Start creating tasks!

## 🔧 Development Workflow

This project follows **Spec-Driven Development (SDD)** with Spec-Kit Plus:

### The Agentic Dev Stack

```
┌──────────────────────────────────────────────────────────┐
│  1. Specification (WHAT)                                  │
│     • Create specs/[###-feature-name]/spec.md            │
│     • Define requirements, user journeys, acceptance     │
│     • Command: uv specifyplus specify                    │
└──────────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────────┐
│  2. Planning (HOW)                                        │
│     • Generate specs/[###-feature-name]/plan.md          │
│     • Architecture, components, technical approach        │
│     • Command: uv specifyplus plan                       │
└──────────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────────┐
│  3. Tasks (BREAKDOWN)                                     │
│     • Generate specs/[###-feature-name]/tasks.md         │
│     • Atomic, testable work units with acceptance        │
│     • Command: uv specifyplus tasks                      │
└──────────────────────────────────────────────────────────┘
                         ↓
┌──────────────────────────────────────────────────────────┐
│  4. Implementation (CODE)                                 │
│     • Claude Code generates code from tasks              │
│     • Test-driven development (write tests first)        │
│     • Command: uv specifyplus implement                  │
└──────────────────────────────────────────────────────────┘
```

### Branching Strategy

```
main (production-ready code)
 ├─ 001-cli-todo-app (Phase I)
 ├─ 002-database-setup (Phase II Stage 1)
 ├─ 003-backend-api (Phase II Stage 2)
 └─ 004-frontend-nextjs (Phase II Stage 3-5)
```

**Workflow**:
1. Create feature branch: `git checkout -b 005-new-feature`
2. Develop with Claude Code following specs
3. Test thoroughly (must pass all tests)
4. Merge to `main` via Pull Request
5. Delete feature branch after merge

## 🌍 Deployment

### Backend Deployment (Railway)

1. **Create Railway Project**
   ```bash
   # Install Railway CLI
   npm install -g @railway/cli

   # Login
   railway login

   # Initialize
   cd backend
   railway init
   ```

2. **Configure Environment Variables**
   - Go to Railway dashboard → Your Project → Variables
   - Add:
     - `DATABASE_URL` (Neon connection string)
     - `JWT_SECRET_KEY` (same as frontend)
     - `CORS_ORIGINS` (your Vercel frontend URL)

3. **Deploy**
   ```bash
   railway up
   ```

**Live Backend**: `https://your-backend.railway.app`

### Frontend Deployment (Vercel)

1. **Push to GitHub**
   ```bash
   git push origin main
   ```

2. **Import to Vercel**
   - Go to [vercel.com](https://vercel.com)
   - Click "New Project"
   - Import your GitHub repository
   - Root Directory: `frontend/`
   - Framework Preset: Next.js

3. **Configure Environment Variables**
   In Vercel dashboard → Settings → Environment Variables:
   ```
   DATABASE_URL=postgresql://...
   BETTER_AUTH_SECRET=your-secret-32-chars
   BETTER_AUTH_URL=https://your-app.vercel.app
   NEXT_PUBLIC_API_URL=https://your-backend.railway.app
   JWT_SECRET_KEY=your-jwt-secret
   RESEND_API_KEY=re_your_api_key (optional)
   RESEND_FROM_EMAIL=noreply@yourdomain.com (optional)
   ```

4. **Deploy**
   - Click "Deploy"
   - Vercel auto-deploys on every `git push`

**Live Frontend**: `https://your-app.vercel.app`
