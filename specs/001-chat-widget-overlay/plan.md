# Implementation Plan: Chat Widget Overlay

**Branch**: `001-chat-widget-overlay` | **Date**: 2026-01-20 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/001-chat-widget-overlay/spec.md`

## Summary

Convert the current full-page chat experience at `/chat` to a floating widget overlay on the dashboard page. The widget appears in the bottom-right corner, toggleable via a Floating Action Button (FAB). Users can interact with the AI chatbot while viewing their task list, and the dashboard updates in real-time when the AI creates, updates, or deletes tasks. This requires extracting reusable chat components from the monolithic ChatInterface, creating a shared state context for task synchronization, and implementing a widget container with minimize/close functionality.

**Constraints**: No WebSocket (use existing SSE), frontend-only changes (backend unchanged), maintain mobile usability
**Scale/Scope**: Single-user session, ~100 tasks max per user, single active widget per browser tab

## Implementation Phases

### Phase 1: Core Infrastructure (P1 Critical)

**Goal**: Create the foundational contexts and hooks for state sharing.

1. **TaskContext** - Shared task state between dashboard and widget
   - State: tasks[], loading, error
   - Methods: fetchTasks, addTask, updateTask, deleteTask
   - Auto-refresh callback mechanism for widget-triggered updates

2. **ChatWidgetContext** - Widget visibility state
   - State: isOpen, isMinimized, threadId
   - Methods: open, close, minimize, restore
   - Persistence to localStorage for session continuity

3. **Type definitions** - Widget state types

### Phase 2: Widget Components (P1 Critical)

**Goal**: Build the widget UI components.

1. **ChatWidgetFAB** - Floating action button (fixed position)
   - Click handler to toggle widget
   - Chat icon with optional notification badge
   - Always visible on dashboard

2. **ChatWidget** - Main widget container
   - Fixed position bottom-right
   - Header with title, minimize, close buttons
   - Body: ChatMessages + ChatInput
   - Responsive sizing (350-400px desktop, full-width mobile)

3. **Portal component** - Render widget outside DOM hierarchy

### Phase 3: Chat Component Extraction (P1 Critical)

**Goal**: Extract reusable pieces from monolithic ChatInterface.

1. **ChatMessages** - Message display component
   - Accept messages array as prop
   - Include MessageContent, FormattedTaskList, TaskCard
   - Auto-scroll behavior

2. **ChatInput** - Input component with send button
   - Accept onSend callback
   - Include VoiceInput integration
   - Loading state during AI response

3. **useChatMessages** - SSE streaming hook
   - Handle thread creation
   - Stream message responses
   - Parse tool call events for task operations
   - Trigger TaskContext refresh on task operations

### Phase 4: Real-Time Task Sync (P1 Critical)

**Goal**: Dashboard updates when AI modifies tasks.

1. **useTaskSync** - Synchronization hook
   - Listen for SSE tool_call events (add_task, complete_task, delete_task, update_task)
   - Call TaskContext.fetchTasks() after AI operations
   - Debounce rapid successive operations

2. **Modify TodoList** - Consume TaskContext
   - Replace local todos prop with context
   - Remove internal fetch logic (moved to context)
   - Maintain existing filter/search functionality

3. **Modify Dashboard page**
   - Wrap with TaskProvider
   - Wrap with ChatWidgetProvider
   - Include ChatWidgetFAB and ChatWidget

### Phase 5: Polish & Responsive (P2/P3)

**Goal**: Minimize/restore, close, responsive behavior, persistence.

1. **Minimize/Restore** - Widget state transitions
   - Animated collapse to FAB
   - Preserve conversation on minimize
   - Badge indicator for new messages while minimized

2. **Responsive behavior**
   - Mobile (<768px): Near full-width widget
   - Tablet (768-1024px): 400px width
   - Desktop (>1024px): 380px width, 500px height

3. **State persistence**
   - Save isOpen/isMinimized to localStorage
   - Restore on page refresh
   - Clear on explicit close (optional)

## Data Flow for Real-Time Updates

```
User types: "Add task buy groceries"
    ↓
ChatInput → onSend(message)
    ↓
useChatMessages → POST /api/chatkit/threads/{id}/messages
    ↓
Backend AI → Calls add_task MCP tool
    ↓
SSE Stream → event: tool_call, data: {name: "add_task", result: {...}}
    ↓
useTaskSync → Detects tool_call event
    ↓
TaskContext.fetchTasks() → GET /api/{user_id}/tasks
    ↓
TodoList re-renders with new task (< 2 seconds)
```
